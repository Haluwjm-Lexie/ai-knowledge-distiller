# AI Knowledge Distiller V1.2｜Obsidian 集成增补规范

> 本规范是在 V1.1 正式规范上的**新增层**，不得替代/改写 V1.1 阶段 0、A、B 与终止分支。

## 1. 模式与授权

- 同一个 Skill 提供两种运行模式：**Obsidian 知识库模式（默认目标）**与**普通 Markdown 模式**。首次使用若未得知可访问的 Vault 路径，先询问是否连接 Obsidian，或使用普通 Markdown；不因默认模式而默认拥有路径、读取或写入权限。
- 普通 Markdown 模式可以产生完整的正式 Markdown，但**禁止假称已与既有 Vault 去重**。可依据用户实际提供的其他笔记做局部对照，并报告范围。
- Obsidian 模式必须获得 Vault 路径及读取许可，确认实际可达。读取与写入分离：**阶段 A 批准/Markdown 生成批准，不等于 Vault 写入授权**。
- 来源包括 X、网页、文章、GitHub 项目、转写稿、现有 Markdown；无法取得正文不可编造。

## 2. 检索分层，不靠同主题决定重复

1. 从新资料提取指纹：原始 URL、标题/别名、作者、项目仓库、产品/术语、3～8 个高信息量关键词、1～3 个独特短语、原子知识点。区分准确提供与推断。
2. 在可访问 Vault 的 Markdown 目录中检索，排除 `.git`、`.obsidian`、隐藏临时/构建目录；首先相同 URL，再文件名/标题/别名、专有词、标签/主题/标题层级、独特短语、正文关键词。YAML 不完整时仍搜索标题和正文。`rg` 可用时优先利用，或用只读脚本定位候选。
3. 报告检索文件总数、排除范围、查询指纹与是否完整覆盖。通常提出 3～5 篇重点候选，但**不能因为 top-K 截断而声称全库没有相似知识**。
4. 读取真正相关的上下文；长转写稿按段落和行号定位，必要时向前后扩大读取，**不能只从搜索命中行推断全文含义**。
5. 对命中笔记分类：**正式知识笔记 / 原始资料（课程转写、访谈记录、采集原文）/ 待确认**。综合目录、YAML、正文形式及用途；没有 YAML ≠ 原始资料。原始资料默认只读证据，默认不是直接合并目标。
6. 逐条比较已有知识与新内容：完全已存在、细节变深、新操作/证据/边界/资源、冲突、仅相邻主题。评分只用于排序候选，不能用于自动跳过或强制合并。相同 URL 也不代表内容无变化。
7. 跳过：没有实质新增；合并：有增量且已有适合的**正式笔记**；新建：没有适合的核心主题笔记，或新资料有独立维护用途。若只有长转写稿出现相同词，仍可能建议新建正式笔记并将转写稿作为引用。检索不足则标待人工核对。

## 3. 阶段 A 必须报告（只在实际检索 Vault 时）

- 检索根目录（真实路径）、扫描文件数、排除范围、实际使用的搜索词与原始 URL、状态（已检索/部分检索/未检索）。
- 候选文件：**真实存在的路径**、行号/标题/上下文位置、笔记类别、相似的旧知识点、具体新知识或冲突；无命中就写无直接命中，**不得虚构文件名**。
- 结论：跳过/合并到具体文件/新建候选路径/待人工核对；说明证据限制与风险。
- 对极短低价值资料，允许简短展示必要结论，无需强制冗长表格；若未连接 Vault，不把个人记忆冒充检索结果。
- 在此暂停，等待用户审核。确认跳过后立即结束；禁止偷跑阶段 B。

## 4. 阶段 B 两段授权，禁止静默写入

**A 审核通过**：仅代表可生成正式笔记/候选变更。若用户没授权 Vault 写入，输出普通 Markdown 或位于 Vault 外的候选稿，停止。

**准备写入**：取得用户对具体 Vault 和目标路径的授权意图后：
1. 解析并检查 Vault 根路径与唯一拟写入路径；对符号链接、junction、路径穿越、相对路径或解析失败采取保守阻断；不要修改 `.obsidian`、`.git`、附件或未点名文件。
2. Git 仓库存在且受控；要求工作区干净（包含未跟踪文件），记录分支和 HEAD；Git 不可用或状态不洁净时停止要求人工处理。不得自动 stash/commit/push/reset。
3. 在 Vault **外**生成候选修改文件。最小范围追加/更新，保护既有 Markdown、用户理解、来源和 YAML；旧文不允许无理由整篇重写。
4. 展示目标文件及候选的完整 Diff、所有拟新增/删除字段、来源与内部链接，提示任何有意替换的行；获得**针对本次写入的二次明确确认**。
5. 确认后重新检查绝对路径、Git HEAD、工作区、候选稿校验和；若任何一项变化，立即停止并重新审阅。尽量停止 Obsidian Git 自动提交等并发操作。
6. 仅写明示授权文件。写后查 Git 变更范围、`git diff --check`、候选与产物 SHA-256、YAML 和新链接、旧内容保留。新建文件可能属于未跟踪文件，不能仅依赖 `git diff` 判定其内容。
7. 报告检查结果与异常；不要自动提交。任何撤销、覆盖或修复均先展示范围并取得批准。绝不使用 `git reset --hard`。

**注意**：Git 干净/旧 HEAD 并不等于绝对安全；Git 未跟踪文件、Obsidian 插件并发、大小写和重名、Windows 链接、非法路径及不同解析器的 YAML 差异都可能带来风险。工具检查不取代用户审核与实际 Obsidian 中的复核。

## 5. 可选辅助工具的边界

- `scripts/vault_search.py`：只读搜索候选、行号和上下文；返回技术命中，不判断真正的知识增量；不要将其输出当作全部事实。
- `scripts/vault_guard.py`：只读检查受控路径、Git HEAD/工作区；默认没有写入或覆盖能力；必须由用户明确授权后使用其它写入机制，遵循上述门禁。
- 工具不可运行时可以手工/内置终端只读检索，明确说明缺失项；不可假装已检查。

## 6. 测试证据与开源声明边界

- T11～T14 阶段 A、T12/T13 模拟 Vault 阶段 B 的**测试结果为用户转述的本地 Codex 测试报告**；只是该环境下的结果，不应声称普遍可靠。
- V1.2 新规则与脚本仍应在实际 Codex 安装环境快速验证后再对外标记为已验证。
- 不将任何真实 Vault 路径、私有笔记、历史测试数据或凭据打包入公开仓库。
